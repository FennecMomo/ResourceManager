## 发现与修复

| 级别 | 场景与影响 | 处理与证据 |
| --- | --- | --- |
| P1 | 多个同名下载在实际写文件前可取得同一目标路径，暂停/并行操作可能混用或覆盖数据 | 在 NodeStore 锁内预留数据库中的任务目标，连同 `.rm-part` / `.rm-etag` 一起避让；并行创建 8 个任务的旧代码只产生 1 个不同路径，新用例要求 8 个 |
| P1 | 错误的 HTTP 206 可当作完整文件接受；无哈希的完整旧片段可跳过源版本确认；超量内容在发现大小错误前已写盘；416 可重复重试；重写失败可把旧片段标上新 ETag | 验证 Content-Range、ETag、Content-Length 和流式写入上限，只有有当前哈希证明的完整片段才能直接完成，416 最多回退完整下载一次；新 ETag 在成功打开/截断片段后写入。新增旧代码失败场景修复后通过，额外覆盖无 Content-Length 和片段被占用 |
| P1 | 同一设备各入口分别递增探测代次，晚启动的坏地址可覆盖健康入口成功 | 每轮按设备共享代次并记录成功设备，失败仅影响尚未成功的设备；真实回环节点加同设备慢入口复现旧行为，修复后通过 |
| P2 | 可见目录扫描持有全局数据库锁，慢目录可能阻塞身份、聊天和设置访问 | 快照后在锁外读取文件，返回前重新校验发布及权限；可控慢扫描并发读取身份、撤销/改权限、取消请求共 3 个回归用例 |
| P2 | 路径规则未完整拒绝 Windows 尾点、尾空格及设备保留名，异常别名可能绕过普通资源的目录限制 | 复用严格路径规则；`.git.`、`.git `、保留名和尾点文件名共 4 个输入回归，旧代码其中 3 项未拒绝 |
| P2 | 托盘退出、关闭退出和更新重启未处理未保存的设置；迁移也须在写入待迁移状态前处理草稿 | 统一退出前保存/放弃/继续编辑，保存失败阻止退出，迁移先处理草稿；保留本机控制通道对未保存状态的无弹窗拒绝 |

其他审阅重点：参数化 SQL、分组继承和私发隔离、固定身份密钥与逐请求签名、重放防护、本机管道当前用户限制、更新来源/哈希/差分失败回退、迁移暂存校验及指针切换、引用发布撤销不删除源文件、服务器上传与下载取消、Git 参数与归档边界、反馈凭据加密保存。没有把普通文件传输、目录同步和消息入队状态混作对端已收到文件的证据。
