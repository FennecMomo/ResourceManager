## 需求原文

> 1. 手机在局域网内也可作为设备接入
> 2. 可以直接发布手机上的文件或目录，自制一套通过类型筛选文件的文件浏览器
> 3. 允许通过微信、QQ、飞书等直接分享
> 4. 请求通知权限，有聊天信息或指定资源提醒时弹通知

补充的用户约束：Android 优先；先确定开发方案；沿用能直连就直连的原则，不在同一局域网且未配置直连入口时才需要使用服务器。开发检查不能使用 computer-use、抢焦点或鼠标键盘注入。

## 推荐方向与未定事项

推荐以 Kotlin + Jetpack Compose 实现 Android 客户端，复用现有线协议与兼容测试，不直接引用整个 C# Core。这个选择仍须通过协议样机和 Android 文件/后台服务样机；没有测得框架间的性能、包体或代码复用比例。

拟议首版完成局域网设备、双向文件/文件夹传输、发布、系统分享、点对点聊天和资源提醒。服务器资源功能为后续阶段；服务器聊天、离线消息和系统推送是额外协议工作。此拆分是作者建议，尚未获得用户对最终范围的确认。

优先审查：

- Kotlin 的跨语言协议维护成本，是否比拆分 Core 后使用 .NET Android/MAUI 更合理。
- Android 前台服务用途、通知权限和后台停止后的产品承诺是否成立。
- 自制文件浏览器在 SAF/MediaStore 授权范围内是否满足需求。
- URI 文件、不可 seek 的输入、稳定文件版本与断点续传能否正确配合。
- 服务器资源中继是否被误当作聊天、推送或 NAT 穿透能力。
