# AI 跨设备文件查找（Windows 1.1.0）

当 A 端不清楚文件的准确名称、普通发布目录检索无法满足需求时，A 端 AI 可以申请让 B 端 Codex 在 B 用户指定的目录中查找。双方 ResourceManager 传递请求、结果与文件；B 端使用自己的 Codex 登录和额度。

## 接收端设置与授权

1. 安装并登录本机 Codex CLI，在 ResourceManager 顶部打开“AI 请求”，选择实际的 `codex.exe`。程序不会安装 CLI、修改其账号配置或代替用户登录。
2. 在“目录授权”中选定请求设备、一个具体文件夹并保存。默认每个请求都要单独允许；勾选免逐次授权仅对当前设备和当前目录生效。配置多条免授权目录时，请求须指定对应 scopeId，否则仍等待人工选择。
3. 收到请求后显示不抢焦点的审批窗口，核对设备、需求和目录后点击“允许本次请求”。允许包括本目录的查找、读取必要文本片段及由 A 端按结果文件 ID 请求取回副本。文件清单与片段会交给 Codex 处理。
4. 可拒绝/取消请求；撤销目录授权会取消其正在运行的会话。关闭审批窗口不会自动授权，也不会取消已运行的请求。

## A 端 MCP 流程

- `resource_manager_request_ai_search(deviceId, question, requestId?, scopeId?)`：返回会话 `id`。建议先生成无连字符 GUID 并在重试时复用；重复 ID 不会重复启动。
- `resource_manager_get_ai_request(deviceId, requestId)`：返回 AwaitingApproval、Running、Ready、Sending、Failed、Rejected、Canceled 或 Expired，以及回答和结果文件列表。每个结果有 fileId（字段 id）、相对路径和大小。
- `resource_manager_continue_ai_request(deviceId, requestId, question)`：Ready 后继续追问，沿用已批准目录，不扩展权限。
- `resource_manager_send_ai_result(deviceId, requestId, fileId)`：只接受当前结果中的文件 ID，异步准备私发副本。再次查询取得 messageId/resourceId；随后通过聊天消息和正常下载工具获取文件。Ready、入队、送达、下载完成是不同阶段。
- `resource_manager_cancel_ai_request(deviceId, requestId)`：取消本人的请求和正在准备的副本；已经送达的文件不会被远程删除。
- `resource_manager_list_ai_requests()`：只读查看本机接收到的请求。授权和免授权设置只在接收端界面操作。

## 边界与失败处理

- 本版支持已登记设备的 IPv4 直连，包括已有可直连入口；不新增服务器中继协议，不支持 Android 作为 AI 执行端。双方需升级 Windows 客户端。离线或旧版返回失败，不默默转为公开发布。
- 每次授权从请求创建起有效 30 分钟，最多 10 轮；单次查找最多 10 分钟，单次 CLI 调用最多 3 分钟；文件复制最多 15 分钟。最多同时执行 2 个任务，最多 20 个活跃/待批请求，同一设备每 10 分钟最多 5 个新请求。
- 每轮扫描最多 5,000 个文件、10,000 个目录；先提供最多 1,000 个相对路径，AI 可按关键词继续筛选。每轮最多 5 次模型决策，每次读取最多 8 个文件，每文件最多 16 KiB UTF-8 文本片段，结果最多 20 个文件。大目录应授权更具体的子目录；找不到不表示文件不存在。
- Office、PDF、图片等二进制文件目前只按名称/路径判断，文本不是 UTF-8 时可能无法可靠理解。不是通用远程桌面、终端或任意任务执行功能。
- 文件代理拒绝绝对路径、越界、路径别名、链接/重解析路径和工具凭据目录；不读取 `.git`、`.codex`、`.ssh`、`.aws`、`.azure`、`.env` 等。发送前重新打开并验证真实文件路径，复制到既有私发存储；公开资源列表不暴露结果文件。
- CLI 使用独立空工作目录、临时会话、严格配置，禁用命令执行、本地图片、浏览器、外部插件、应用、记忆和子代理；通过结构化 JSON 返回受限的 read/search/done 请求，实际读取由 ResourceManager 校验。模型生成的路径不能直接作为文件传输授权。
- 自定义权限只给最小运行目录和隔离工作目录读取权限，禁止子进程网络。忽略用户配置与规则，保留现有 CLI 登录。兼容性已针对本机 `codex-cli 0.162.0-alpha.17.2` 验证；不支持隔离参数的版本明确失败，不降级为完全访问模式。
- 客户端重启后未完成任务标为失败，不自动重放；现有请求状态和目录规则保存在本机资料库。撤销设备或目录后不能继续读取/取文件。CLI 不可用、未登录、限流、超时或模型越界请求均明确失败。

实现参考 [Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)、[权限配置](https://learn.chatgpt.com/docs/permissions)及本机 CLI 的 help/features。当前本机禁用图片工具使用 `features.view_image=false`；以严格配置与实际运行校验为准。

## 验证

隔离测试覆盖逐次授权、免授权设备隔离、撤销、过期、重复请求、限流、路径越界、取消与重启恢复。三设备 HTTP 测试覆盖签名、第三方拒绝、结果文件私发和实际内容下载。WPF 检查全程不显示窗口。真实 CLI 测试只使用临时目录中的合成资料，不读取或发送用户资料。

2026-10-15 验证结果：173 项核心测试通过（含 8 项 AI 请求专项）；9 项 AI 授权界面、22 项发布界面和 83 项帮助/布局检查通过。真实 Codex CLI 完成受限 read 决策、文本片段读取及结果返回。打包程序提供 45 个 MCP 工具，已在固定安装路径后台运行 1.1.0，`ready: true`，MCP 状态及 AI 请求列表实际调用通过，安装前后 SHA-256 一致。本机当前没有配置 AI 执行目录或免授权规则；使用前由接收端用户选择 CLI 和授权目录。真实第二台电脑及日常操作体验待人工验收，未宣称已通过。
