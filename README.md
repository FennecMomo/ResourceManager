# ResourceManager 资源管理器

ResourceManager 用于设备之间的文件共享、聊天和资源管理。Windows 客户端可以直接在局域网内使用，也可以连接自建服务器，浏览跨网络资源或上传副本供离线下载；Android 测试版提供手机与电脑之间的局域网互通。

| 组件 | 当前版本 | 运行环境与定位 |
| --- | --- | --- |
| Windows 客户端 | **1.0.0** | Windows x64，WPF 桌面程序，自包含单文件，无需另装 .NET |
| Android 客户端 | **0.1.2 测试版** | Android 10 及以上，以会话和发送文件为主，目前限局域网互通 |
| 独立服务器 | **0.3.0** | Windows / Linux x64，提供工作空间、资源中继、持久存储及反馈管理 |

各端独立版本。Windows 1.0.0 发布不表示 Android 已达到正式版；手机熄屏通信仍有已知问题，详见下文。

## 下载与开始使用

- [下载 Windows 1.0.0](https://github.com/FennecMomo/ResourceManager/releases/tag/v1.0.0)：选择附件 `ResourceManager.exe`。`SHA256SUMS.txt` 用于核对下载内容；差分附件由客户端自动使用，无需手动合并。
- [全部正式发布](https://github.com/FennecMomo/ResourceManager/releases)及 [CI 构建记录](https://github.com/FennecMomo/ResourceManager/actions/workflows/ci.yml)：CI 附件属于构建产物，版本与稳定性以对应提交和发布说明为准。
- [Android 使用与构建](ResourceManager.Android/README.md)、[服务器部署](docs/server-deployment.md)。服务器和 APK 使用各自的交付包，Windows EXE 不包含它们。

Windows 完整包约 200 MiB，包含运行时。下载后放在固定位置运行；首次运行如防火墙询问，请按实际网络用途允许访问。

1. **设置存储位置。** 首次启动选择资料目录，填写昵称和头像。以后启动会沿用已保存配置；设备身份不随昵称或头像改变。
2. **连接设备。** 在“设备”刷新局域网设备，或手动填写对方地址和端口，默认 TCP `37642`。候选设备、身份验证与资源加载分阶段显示；暂时离线的设备仍保留在列表。
3. **发布资源。** “我的发布”采用左侧分组/资源树、右侧详情。右上角“发布”菜单选择文件或文件夹；“新建分组”位于资源树标题旁。选择引用原位置或复制副本，并按需要设置分组权限。
4. **聊天或发送文件。** 从设备进入会话，发送文字、已有发布的资源卡片，或直接私发文件/文件夹。无需为了私发而先公开发布。
5. **下载与收藏。** 浏览对方资源并选择保存位置，在“下载”暂停、继续任务；收藏保存资源入口，不自动复制文件。
6. **保持共享。** Windows 关闭窗口默认缩到托盘并继续共享；托盘的“退出并停止共享”才会退出，可在设置调整关闭行为和开机启动。

右上角“帮助”提供按模块划分的截图、控件红框和逐步指引。“更新历程”以可搜索的竖向时间轴列出 41 个 Windows 版本，内容内置，离线可读。

需要固定安装位置和桌面快捷方式时，在源码目录运行以下脚本；`SourceExe` 指向已下载的 EXE。已有客户端须先正常退出。

```powershell
./scripts/install-desktop-shortcut.ps1 -SourceExe 'D:\Downloads\ResourceManager.exe'
```

## 文件、权限与聊天

| 功能 | 当前行为 |
| --- | --- |
| 引用发布 | 读取原文件/文件夹，源内容变化会影响发布；撤销发布不删除原件 |
| 复制发布 | 在资料目录保存受管副本，原件后续变化不影响副本；撤销时删除该副本 |
| 分组管理 | 支持嵌套分组、移动、备注；详情显示实际权限及继承来源 |
| 访问权限 | 公开、私有和设备白名单；子分组可继承或覆盖，每次目录和下载请求均检查权限 |
| 设备身份 | 首次连接自动信任公钥，后续校验固定设备身份、请求签名及重放；密钥变化明确报错 |
| 私发资源 | 单独准备文件/文件夹副本，仅供对应收件设备访问，不进入公开资源目录或更新源 |
| 聊天 | 气泡、资源卡片、1–5 行输入框、草稿、未读、通知和静音；离线消息在发送端持久排队，7 天未送达后停止自动重试 |
| 下载 | 保留目录结构，支持暂停与续传；校验续传响应、版本及大小，同名任务使用独立目标和临时文件 |

“已送达”表示接收方已接收消息，不表示已阅读或已下载附件。私发文件仍需发送方在线提供下载；清空本机会话会清理该会话的私发副本，已被对方保存的文件不会被收回。

当前点对点 HTTP 使用身份签名和访问控制，**不提供传输内容加密**。首次自动信任也不等于人工核验对方身份。资源权限与兼容边界见 [资源权限与设备身份](docs/resource-permissions.md)。

## 设备发现与跨网络连接

- **局域网：** UDP `37643` 发现与历史入口探测并行推进，身份验证和目录读取分开；超时、失败冷却及刷新批次保护避免慢设备拖住整轮刷新。离线不等于失效，不因一次超时删除设备记录。
- **手动直连：** 保存明确的设备地址/端口；同一设备可有多个入口，某个旧入口失败不会覆盖本轮其他入口的成功结果。
- **隔路由器：** 在设置中保存路由器 WAN IPv4，扫描映射端口 `48001–48099`。需要路由器支持 UPnP，并预先存在至少一条可访问的设备映射作为引导。访客网络、AP 隔离或上级网络限制无法由软件绕过。
- **服务器：** 可用公网 HTTPS 域名或地址加入多台自建服务器。已有直连连接或局域网确认可达时使用直连；跨网络且没有配置直连连接时使用服务器中继。已配置直连失败不会自动改走中继。

路由器发现只协调设备的端口映射，文件直接传给目标设备。退出程序保留外部映射；需要移除时使用设置中的“删除本机外部映射”。

## 自建服务器与离线资源

服务器是可选组件，局域网基础共享不依赖它。服务器 0.3.0 提供两种资源方式：

| 方式 | 文件存放位置 | 发布者离线后 |
| --- | --- | --- |
| 发布本机资源/分组到服务器 | 发布者电脑；服务器同步目录并按需中继 | 保留目录，无法从离线发布者下载 |
| 上传服务器副本 | 服务器持久存储 | 仍可下载已完整上传的内容 |

上传支持文件、文件夹、分片、暂停续传、重启恢复及逐文件 SHA-256 校验，完成后原子发布。支持服务器收藏、所有者修改权限和删除资源；未完成内容不可下载。目前没有人为配置的上传配额或保留期限，仍受实际磁盘和网络条件限制。

公网部署通过 HTTPS 反向代理只开放工作空间接口；反馈接口仍按可信局域网使用。默认业务端口 TCP `37644`、反馈发现 UDP `37645`，管理页仅在服务端本机 `http://127.0.0.1:37646/admin/` 提供，不应直接暴露到公网。部署包、systemd、Caddy、Docker、备份恢复及审计说明见 [服务器部署文档](docs/server-deployment.md)和[服务端说明](ResourceManager.Server/README.md)。

## 版本更新

Windows 更新检查同时覆盖 GitHub 正式发布、局域网已发布安装包，以及已绑定服务器中的可用更新资源；服务器持久存储的更新包在上传者离线后仍可获取。候选按版本和哈希合并，来源与信任信息在界面展示。

GitHub 正式发布支持 **xdelta3 差分更新**：只有当前 EXE 的版本和哈希符合补丁清单时才下载差分，在磁盘上合成新版，核对完整 EXE 的 SHA-256 后正常退出并替换。缺少补丁、基线不匹配或合成失败时回退完整包；这仍然需要重启程序。发布时补丁达到完整包的 60% 或生成失败，则只提供完整包。

更新前会处理未保存设置。资料目录独立于 EXE，覆盖升级无需清空设备、发布或聊天记录。差分工具及第三方许可见 [xdelta3 更新组件](tools/delta/README.md)。

## AI / MCP 接入

Windows 1.0.0 内置 **38 个本机 MCP 工具**，覆盖设备刷新、设备/服务器资源检索、发布维护、聊天和私发、下载、上传、收藏、权限及更新状态查询。

最方便的接入方式是打开 **帮助 → MCP 与 AI**，复制完整接入指令给所使用的 AI。指令动态包含当前运行 EXE 的绝对路径，以及维护在仓库中的 Skill 模板；由 AI 根据宿主能力配置 MCP 和 Skill，不限定 Codex。云端 AI 或不支持本机 stdio / Skill 的宿主需要采用其支持的接入方式，不能直接访问本机 EXE。

通用入口为：

```text
<当前 ResourceManager.exe 的绝对路径> --mcp
```

MCP 通过当前 Windows 用户专用命名管道连接已经运行的客户端，不操作桌面。发布、传输和消息发送是异步操作，AI 应查询最终完成或送达状态，不能把入队当作成功。完整清单、参数边界和配置示例见 [MCP 文档](docs/mcp.md)，模板见 [ResourceManager Skill](ResourceManager.App/Assets/Ai/resource-manager/SKILL.md)。

## 其他桌面功能

- **Git 协作：** 从本地仓库建立项目、加入附近项目、查看各设备提交线，交换 Git bundle 与选中历史中的 LFS 对象。自动同步只允许快进；分叉进入收件引用等待处理。需要 Git，不替代完整 Git 客户端。
- **反馈：** 通过局域网反馈服务提交问题和附件、查询处理状态；也可授权自己的 GitHub 账号提交。GitHub 集成要求配置 GitHub App Client ID，未配置的构建不能直接使用此入口；不内置共享访问令牌。
- **后台管理：** [本机控制通道](docs/local-control.md)支持只读状态、正常退出和后台换版，无需激活窗口；有未保存编辑时自动退出会拒绝执行。

## Android 测试版

Android 0.1.2 默认进入消息，四个主入口为“消息、设备、我的发布、传输”，设置从顶部进入。支持局域网设备发现、文字与文件卡片、文件/文件夹发布与私发、资源浏览、暂停续传，以及接收外部分享后选择会话确认发送。

打开应用自动启动或恢复共享，界面区分实际服务状态与保存的共享意愿；通知中可停止共享，重新进入应用会再次启动。当前使用通用前台服务、网络回调、CPU 唤醒锁和组播锁，没有厂商专属逻辑。

**已知限制：真机熄屏后仍可能无法通信，此项暂缓处理，尚未验证解决。** 常驻通知存在不能证明网络正常。Android 当前不包含服务器绑定、公网中继、推送唤醒或自动 APK 更新。

测试包沿用原包名及测试签名，保留资料时请覆盖安装，不要先卸载。详细使用、权限、系统分享、构建和验证边界见 [Android README](ResourceManager.Android/README.md)及[验证记录](ResourceManager.Android/validation.md)。

## 资料位置与迁移

默认资料目录为 `%LOCALAPPDATA%\ResourceManager`，首次启动可更改。SQLite、设备身份、发布副本、聊天、反馈、Git 协作、日志及更新缓存都使用所选目录。`%LOCALAPPDATA%\ResourceManager.bootstrap\storage.json` 仅保存位置指针和迁移状态。

通过“设置 → 存储位置”迁移到新的空目录：先停止共享与任务，复制并校验文件和数据库，调整内部路径后切换指针，原目录保留。引用源文件、用户指定的下载目标与其断点文件保持原位置，清理旧目录前须确认这些文件仍在使用与否。

缺失数据库会初始化新库；损坏或无法使用的资料会进入恢复流程或改用新资料目录，旧文件保留。新建资料不等于恢复旧记录，需要保留历史时应选回原有效目录。磁盘用量和剩余空间显示在侧栏，复制、下载和更新前检查空间。

## 开发与验证

桌面和核心使用 .NET 10，Windows UI 使用 WPF；节点与独立 ASP.NET Core 服务端使用 SQLite 持久化。Android 使用 Kotlin、Compose 和 Android Keystore。

在 Windows 安装 .NET 10 SDK 后，从仓库根目录运行：

```powershell
dotnet build ./ResourceManager.slnx -c Release
dotnet test ./ResourceManager.Tests/ResourceManager.Tests.csproj -c Release
dotnet publish ./ResourceManager.App/ResourceManager.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -o ./dist/win-x64
# 帮助与更新历程的隔离 WPF 检查，不显示窗口
dotnet run --project ./tools/HelpChecks
# 后台读取正在运行的客户端状态
./tools/client-control.ps1 -Action Status
```

其他隔离 UI 检查位于 `tools/SettingsChecks`、`NotificationChecks`、`PublicationChecks`、`ServerChecks` 和 `ChatChecks`；Android 构建使用 `tools/android-build.ps1`。测试应使用隔离资料，避免操作日常使用的窗口与数据。

Windows 1.0.0 发布前完成 **152 项核心测试、266 项隔离 WPF 检查**，以及打包程序的 MCP 检查；问题修复、证据和未覆盖边界见 [1.0.0 审查记录](docs/reviews/desktop-1.0.0-review.md)。这些结果不代表所有真实网络与硬件环境均已人工验收。
